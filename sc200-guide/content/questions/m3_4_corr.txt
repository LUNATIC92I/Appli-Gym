### Hameçonnage cliqué : e-mail et clic
@ niveau=I sub=corr ref=xdr-t-EmailEvents,xdr-t-UrlClickEvents
?: **Besoin :** identifier les destinataires d'e-mails classés hameçonnage qui ont cliqué sur une URL du message. Quelle requête de corrélation est correcte ?
+: ```kqlx
EmailEvents
| where Timestamp > ago(7d)
| where ThreatTypes has "Phish"
| project NetworkMessageId, RecipientEmailAddress, SenderFromAddress, Subject
| join kind=inner (
    UrlClickEvents
    | where Timestamp > ago(7d)
    | project NetworkMessageId, AccountUpn, Url, ActionType, IsClickedThrough, ClickTime = Timestamp
  ) on NetworkMessageId
| where RecipientEmailAddress =~ AccountUpn
| project ClickTime, AccountUpn, SenderFromAddress, Subject, Url, ActionType, IsClickedThrough
```
-: ```kqlbad
EmailEvents
| where Timestamp > ago(7d)
| where ThreatTypes has "Phish"
| join kind=inner (UrlClickEvents) on RecipientEmailAddress
```
|| UrlClickEvents n'a pas de colonne RecipientEmailAddress ; la clé commune est NetworkMessageId (puis AccountUpn).
-: ```kqlx
EmailUrlInfo
| where Timestamp > ago(7d)
| summarize count() by UrlDomain
```
|| Statistiques de domaines présents dans les e-mails, sans clics ni destinataires.
-: ```kqlx
UrlClickEvents
| where Timestamp > ago(7d)
| where ActionType == "ClickBlocked"
```
|| Ne garde que les clics bloqués, sans lien avec le verdict hameçonnage du message.
=: **NetworkMessageId** relie un message (EmailEvents) aux clics associés (UrlClickEvents). La condition `RecipientEmailAddress =~ AccountUpn` garantit que le clic provient bien du destinataire (un message peut avoir plusieurs destinataires). **IsClickedThrough** révèle les utilisateurs ayant ignoré l'avertissement.
T: La clause `on` n'accepte que des égalités de colonnes : les conditions supplémentaires (ici l'égalité insensible à la casse entre deux colonnes) se placent dans un `where` après la jointure. ThreatTypes est une chaîne (par exemple « Phish, Malware ») : on utilise `has`.
R: Les clics des destinataires sur des messages d'hameçonnage, avec l'URL et le résultat (autorisé/bloqué).
S: UrlClickEvents ne couvre que les URL réécrites/protégées par Safe Links.
M: Ajouter une troisième étape : connexions Entra (EntraIdSignInEvents ou SigninLogs) du même utilisateur dans l'heure suivant le clic, depuis une IP inhabituelle.
!: E-mail ↔ clic = NetworkMessageId (+ RecipientEmailAddress = AccountUpn).

+: ```kqlx
let PJ = EmailAttachmentInfo
| where Timestamp > ago(7d)
| where ThreatTypes has "Malware"
| distinct SHA256, FileName, RecipientEmailAddress;
DeviceProcessEvents
| where Timestamp > ago(7d)

| project Timestamp, DeviceName, AccountUpn, RecipientEmailAddress, FileName, ProcessCommandLine
```

```kqlx
EmailAttachmentInfo
| where Timestamp > ago(7d)
| join kind=inner (DeviceProcessEvents) on FileName
```
|| Joindre sur le nom de fichier est peu fiable (renommage, noms génériques) et très coûteux sans filtre temporel à droite.


```kqlx
EmailAttachmentInfo
| where Timestamp > ago(7d)
| where ThreatTypes has "Malware"
```

R: Les exécutions sur les postes de fichiers reçus en pièce jointe malveillante.
